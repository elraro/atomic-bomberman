# The free asset set

People without a copy of the original game can play: when no original data is found (or with `--free`), the program uses a set of graphics, sounds, music and arenas that it makes itself. Nothing in it is taken from the original game's files, and no art or sound files are stored in this repository: everything is produced by code under `src/free/`. It is covered by the program's own licence.

## What it consists of

| Part | How | Where |
|---|---|---|
| Sprites: players, bombs, flames, powerups, level extras, campaign enemies, tiles of all 11 levels | Drawn at start-up by a small software canvas (shapes with soft edges) | `free_art.cpp`, `makeFreeArt()` |
| Full-screen pictures: main menu, backgrounds, playfields, results, draw, victory, team | Drawn when first shown | `makeFreePicture()` |
| Text font | The classic 5 x 7 dot-matrix character shapes, stretched to the 8 pixels a character the screens were laid out for | `makeFreeFont()` |
| Sound effects and six looping tunes | Synthesised (oscillators, noise, envelopes; a small tune generator with fixed seeds) and written once as `.wav` | `free_sound.cpp` |
| Twenty-six voice lines in a robot voice ("ha ha ha", "oh no", "winner", "hurry up", ...) | A small speech synthesiser: a buzz or noise source through three moving resonances (formants), with noise bands and bursts for consonants | `speak()` in `free_sound.cpp` |
| Eight arenas, level extras for seven levels, three campaigns (24 stages), the tuning table, a manual and an about page | Written once as files in the formats the game already reads | `free_data.cpp` |

The files go to `free-assets` in the per-user data folder (Linux: `~/.local/share/atomic-bomberman-modern/atomic/free-assets`, about 10 MB, mostly the tunes). A marker file names the set's version; when the program is updated and the version differs, the folder is rewritten. The game then treats that folder like any game data folder, which is why almost nothing else in the program had to change: only the sprite bank knows that pictures come from code instead of `.ani` and `.pcx` files. The dedicated server uses the same folder (without sounds) for its arenas.

The tuning table written there is the program's built-in defaults, i.e. the numbers already present in `src/game/values.cpp`.

## Design choices

- **Its own look.** The player figure is a small robot with a visor, deliberately not the helmeted character of the original series. Level themes keep the original's level numbers (because levels carry rules: ice, regenerating bricks) but the tiles are new.
- **The same names.** The renderer asks for sprites by the sequence names of the original's animation files ("walk north", "flame tipeast green", ...). The free set answers to the same names, so there is one renderer.
- **Player colours** are applied to marked pixels at upload time, in place of the original's palette remap tables.
- **Voices** are synthetic and few: one to five lines for each kind of moment (a death, a string of bombs, a good pickup, a disease, a draw, a match win, the hurry warning, leaving). Each of the nine diseases has its own line ("so slow", "too fast", "no bombs", "oops", "tiny", "run run run", "watch out", "where am I", "wrong way"), played one time in three as in the original. The original has hundreds of recorded lines; here each series has one to five.
- **The intro** is the title screen alone, with the title call; the original's movie and logo screens have no counterpart.
- **Campaigns** (the original's hidden mode: C five times on the player list): `first-steps` (6 stages), `night-shift` (7, ghosts) and `gauntlet` (11, one per level). The stages, their names and their difficulty curve are new and untuned: nobody has played them.

## Checked

- `ab_tests` "free assets": every sequence, picture and sound id the game uses exists; frames are well-formed; the colour reaches only the marked pixels; no glyph is blank; the eight arenas load, give every player a free start cell, and a round of computer players on each comes to an end; the folder is written, completed with sounds on request, and not rewritten when up to date.
- Screens captured from unattended runs with `--free`: menu, level screen, options, manual, a match on three levels, a result screen.

## Not checked

- **Nobody has listened to the sounds, the music or the voices.** They are generated by formula and verified only to be non-silent and unclipped. For the voices the vowels' resonances were measured and sit where the tables say (e.g. 250 and 2275 Hz for "ee"), which shows the synthesiser does what it is meant to; whether the words can be understood is a question for ears. They may well need tuning.
- How the animations look in motion (only still frames were looked at).
- Windows: the code is the same, and CI runs the test there, but the game window with the free set has not been seen on Windows.
